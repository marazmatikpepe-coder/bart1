# Bart — веб-ассистент

Статический сайт (без сборки): работает на GitHub Pages.

## Запуск
1. Создайте репозиторий на GitHub, загрузите в него **содержимое** этой папки (index.html в корне).
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)`. Через минуту сайт откроется по адресу `https://ИМЯ.github.io/РЕПО/`.
3. До подключения Firebase сайт работает в локальном режиме (чаты в браузере).

## Firebase (аккаунты и синхронизация)
1. Project settings → Your apps → Web (`</>`) → скопируйте `firebaseConfig` в `js/firebase-config.js`.
2. Authentication → Sign-in method: включите **Email/Password** и **Google**.
3. Authentication → Settings → Authorized domains: добавьте `ИМЯ.github.io`.
4. Firestore Database → Rules:
```
rules_version = '2';
service cloud.firestore { match /databases/{d}/documents {
  match /users/{uid}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == uid; }
}}
```
5. Realtime Database → Rules:
```
{ "rules": { "presence": { "$uid": { ".read": "auth != null && auth.uid == $uid", ".write": "auth != null && auth.uid == $uid" } } } }
```
Почта: Firebase шлёт **ссылку** подтверждения (не код); текст письма меняется в Authentication → Templates.
Google: на мобильных вход через всплывающее окно; из встроенных браузеров (Telegram, Instagram) Google не пускает — откройте ссылку в Chrome/Safari.

## Как работают модели
Два провайдера: **Groq** и **ModelScope** (`js/config.js`, ключи в base64). Названия не зашиты: сайт берёт актуальные списки моделей и выбирает подходящие, мёртвые (404) пропускает.
- текст → Groq `gpt-oss-120b`, запасные: Llama 3.3 70B, Qwen, затем DeepSeek на ModelScope;
- код и длинные файлы → ModelScope **DeepSeek (самая новая версия из списка, V4 → V3.2…)**, запасные — Groq;
- картинки на входе → Groq vision, запасная — Qwen-VL на ModelScope;
- картинка + код/файл → два шага: vision читает картинку, потом код-модель отвечает;
- «нарисуй…» → Groq переводит запрос в английский промпт, **ModelScope Qwen-Image** рисует (асинхронная задача, до ~2 минут), запасной вариант — Pollinations; результат сохраняется на imgbb.
- Лимиты: при 429 сайт ждёт указанное время и повторяет, затем идёт к следующей модели; история обрезается под бюджет провайдера (старые файлы заменяются пометкой), чат хранится компактно (лимит Firestore 1 МБ).
Под каждым ответом показана модель. Файлы: txt/md/код/json/csv, PDF (до 40 стр.), DOCX; в чат уходит до 30 000 символов.

## Ваши иконки
Сайт сначала показывает встроенные иконки, а если в `assets/icons/` лежит `ИМЯ.png` (menu, plus, send, attachFile, camera, delete, search, copyIcon, download, close), подставляет вашу.
Скачать все 105 иконок в репозиторий: вкладка **Actions → Fetch icons → Run workflow** (список в `icons.txt`). Если Actions не даёт писать: Settings → Actions → General → Workflow permissions → Read and write.
Или положите PNG в `assets/icons/` вручную.

## Прокси для ModelScope (если картинки/DeepSeek не работают из браузера)
ModelScope может не разрешать запросы прямо со страницы (CORS). Тогда в чате появится пометка «Qwen-Image недоступен: … CORS», а DeepSeek будет пропускаться. Решение — бесплатный Cloudflare Worker: код в `proxy/worker.js` (инструкция в комментариях), адрес воркера вписать в `js/config.js` → `PROXY`.

## Лимиты и стабильность
В запрос идут только **последние 8 сообщений**; свежее — целиком, старое — сокращённо. Если провайдер отвечает «слишком большой запрос» (413/429 по токенам), сайт читает цифры из ошибки и сам сжимает запрос. Запросы к провайдерам идут с паузой (Groq ≈ 1 в 2 сек), ответ печатается плавно, скролл не дёргается, если вы листаете вверх. Кнопка 🔧 в сайдбаре проверяет Groq, прокси, DeepSeek, Qwen-Image и запасной Flux; `?debug` в адресе показывает под ответом, какая модель отвечала.

## Файлы от Bart
Всё, что Bart выдаёт файлом (html, pdf, docx, xlsx, pptx, csv, код, ZIP из нескольких файлов), показывается карточкой с кнопками «Открыть / Скачать». PDF/DOCX/XLSX/PPTX собираются прямо в браузере из текста, который пишет модель. Обрезанные по длине ответы Bart сам продолжает (до 6 раз).

## Вложения
Картинки можно отправить **как фото** (сжимаются вдвое, идут альбомом) или **как файл** (оригинал без сжатия): плашка «Фото/Файл» на миниатюре переключает режим. Остальные форматы — см. ниже. Перетаскивание файлов на окно и вставка из буфера работают.

## Файлы, ZIP, голос
- Читает: PDF (текст с сохранением строк таблиц; сканы без текста отправляются как картинки страниц в vision), DOCX, DOC (приблизительно), TXT, RTF, ODT, HTML, EPUB, CSV, XLSX/XLS/ODS (значения ячеек по листам, формулы не показываются), JSON, XML, YAML, TOML, PPTX (текст слайдов), MD, IPYNB, ZIP (список файлов + текст кода внутри), любой текстовый файл и код; картинки JPG/PNG/GIF/WEBP.
- В чат уходит до 30 000 символов файла, дальше текст обрезается.
- Создание ZIP: попросите «создай проект …» — Bart выдаёт каждый файл отдельным блоком с именем, под ответом появляется кнопка «ZIP».
- Голос: кнопка микрофона записывает речь, текст вставляется в поле ввода (распознавание Whisper). Нужен HTTPS (GitHub Pages подходит) и разрешение на микрофон.

## Безопасность ключей
Ключи в `js/config.js` видны любому, кто откроет сайт. Для публичного сайта их стоит заменить на ключи с лимитами или вынести на свой прокси.
